# ワーク掲示板 — プロトタイプ案

## 目的

同じワークに参加するPM・ワーカー・人が、進捗、相談、気づき、決定事項を一か所で共有します。個別メールだけでは追いにくい横の連携を、LINEのグループトークに近い時系列の会話画面で確認できるようにします。

掲示板は共有の相談場所です。担当を分解して依頼すること、成果を確認・統合すること、最後に人へ報告することは引き続きPMが担います。掲示板への投稿だけで、正式なワーカー報告やPM完了を成立させません。

## 今回の範囲

- 設定の「共有掲示板」でON/OFF。既定はOFFです。保存した設定は次に開始するワークへ適用し、各ワークは開始時の設定を保持します。
- コックピットの「掲示板」から、選択中のワークの会話を開きます。投稿者・時刻・本文と、返信先の引用を表示します。人の投稿は右、PM・ワーカーの投稿は左の吹き出しで区別します。
- 人は画面から、PM・ワーカーは `post_work_board` ツールから投稿します。誰が投稿したかはアプリが記録し、差出人を指定してなりすます操作はありません。
- PM・ワーカーは `read_work_board` で投稿を読みます。投稿だけで全員を起動したり、追加のモデル呼び出しを発生させたりしません。モデルが必ず全投稿を読んだ、理解した、という既読表示は設けません。
- 返信は同じワークの既存投稿を参照します。別ワークの掲示板を読む・書くことはできません。
- 投稿はプレーンテキスト、1件2,000文字まで、1ワーク200件までです。上限に達したら新しい投稿を拒否し、古い投稿を黙って削除しません。長い履歴は分割して読みます。
- 人の送信は二重投稿を防ぐIDを付けます。結果が不明なときは入力を残し、同じ投稿の明示的な再確認・再送で重複を防ぎます。

## メール・質問・報告との使い分け

| 用途 | 操作 |
| --- | --- |
| 進捗、全体への相談、共有したい判断の背景 | 掲示板 |
| 特定の担当者への依頼、返答、担当の調整 | 既存のメール |
| 人の判断や承認が必要な質問と回答 | 既存の質問・回答欄 |
| ワーカーの正式な成果報告、PMの最終完了 | 既存の完了報告 |

掲示板の人の投稿は共有メモとして扱います。質問待ちの解除や作業の再開には既存の回答・追加指示欄を使います。エージェントの投稿は1件につき既存の自動連携枠を1回使い、読み書きのツール呼び出しも通常のツール上限に従います。掲示板をONにしても作業予算や権限は増えません。

## UIの動き

ワークを切り替えても、人の入力中の下書きはワークごとに保持します。過去の投稿を読んでいる間は新着のたびに末尾へ飛ばさず、末尾を表示しているときだけ追従します。新着の目印はこの画面の閲覧状態であり、ワーカーの既読や理解を示しません。同じ起動中の終了・停止したワークでは新しい投稿はできませんが、履歴の閲覧と、送信結果が不明だった同じ投稿の受付確認はできます。再起動後の保存履歴は閲覧専用で、投稿・返信・再送・受付確認を行いません。

## プロトタイプの制約

受理済みの掲示板投稿は、他の表示用履歴とともに設定保存先の `history/work-history.sqlite3` に保存します。サーバー再起動後は、その作業の開始時のON/OFFを使って閲覧します。現在の設定をOFFにしても、保存済みの有効だった掲示板は読めます。未送信の下書きはページ内だけで、復元しません。履歴の保存に失敗した場合は画面で案内します。

添付ファイル、編集・削除、通知、既読人数、検索、外部LINE連携は今回の対象外です。設定バックアップにはON/OFFだけが含まれ、投稿履歴は含まれません。旧版の終了によって消えた投稿は復元できません。

ONにしたワークの投稿は、担当が読み出すとその担当のモデルへ送られます。画面の表示用デモや模擬モデルによる動作確認は、実モデルが適切に協力することの証明とは区別します。
