# 社内導入前の確認チェックリスト

文書改訂: 1 / 2026-10-06。動作の確認基準は `0.1.1.dev25`、
ソースコミット `497b549bec320020dd35696ab0871ef45ca832b9` です。
この追加は文書のみで、アプリの版・設定・権限・通信動作を変更しません。

導入担当者が既存の説明と社内要件を照合するための未記入の確認票です。
認証・監査報告・会社の承認済み証明ではありません。項目ごとの確認結果と
未解決事項は組織の承認済みの場所に記録し、秘密や実際の社内アドレスを
この公開文書や Issue に書き込まないでください。

各項目は「未確認 / 確認済み / 対象外」から選び、対象外の理由も記録します。
未確認・未解決の項目を、この文書やテスト成功だけで承認済みにしないでください。

## 1. 導入物と前提条件

- [ ] 対象のソース版・コミット・配布元を確認した。通常版 x64 CPython
  3.11〜3.13（3.13 推奨）はアプリと別に認可・導入し、保守担当を決める。
  Python は同梱せず、自動取得・インストール・更新もしない。
- [ ] CMD、Python、ローカルサーバー、Edge / Chrome の利用可否を確認した。
  アプリを管理者実行せず、SmartScreen、AppLocker、WDAC、ウイルス対策や
  TLS の警告を回避しない。許可されない場合は組織の手順で判断を受ける。
- [ ] アプリの MIT License、依存パッケージ、モデル・API の条件を確認した。
  [requirements.lock](../requirements.lock) 全体が導入対象で、pytest 等の検証用依存も含む。
  固定版・SHA-256 は会社の承認や脆弱性がないことを証明しない。
  `requirements-build.lock` は旧同梱版の履歴で、現在の導入には使わない。

手順・対応対象・禁止事項: [Windows セットアップガイド](WINDOWS_SETUP.md)。

## 2. インストール時の通信と保存先

- [ ] 承認済みパッケージ取得先・proxy・PEM CA、またはオフライン wheelhouse を選ぶ。
  通常モードは既存の pip / proxy 設定を引き継ぐ。wheelhouse は同じソース版の
  lock と対象の Windows アーキテクチャ・Python minor 版に合わせて用意する。
- [ ] wheelhouse モードはインデックス・外部 find-links・pip 設定ファイルを使わず、
  必要な wheel がなければ停止する。オンラインへの自動切り替えはしない。
  両モードともハッシュ照合と依存 wheel のみを使い、依存のソースビルドはしない。
- [ ] ソースを自分が書き込めるローカルフォルダーに全展開する。依存はその中の
  `.venv` に入り、アプリ自身はソースから editable install される。
  別 PC から `.venv` をコピーせず、移動時は新たに展開・セットアップする。

コマンドと失敗時の対処: [Windows セットアップガイド](WINDOWS_SETUP.md) の
「プロキシ・証明書」「オフライン / IT 配布用 wheel フォルダー」。

## 3. 利用時の接続先とデータの扱い

- [ ] PM と許可する全作業者の接続先、検索サービス、取得先 Web サイト、proxy を確認する。
  依頼・許可範囲から読み取ったファイルの内容は選んだモデルに送られ、仲間への連絡で Local から
  クラウドへ共有される場合がある。検索語・URL も送信され、proxy が通信内容を扱う場合がある。
- [ ] 各接続先の保存・再転送・学習利用を社内要件と照合する。アプリは確認しない。
  Local の private IP 制限は会社の承認や外部再転送がないことを保証しない。
  外部送信を禁止する用途では Web を無効にし、全 PM・作業者と下流の扱いを確認する。
- [ ] 初期設定はファイル権限なし・Web 無効だが、Local / OpenAI / Anthropic の
  プロファイルは有効で、モデル名は空欄。承認済み・オフライン専用の設定ではない。
- [ ] インストール用 proxy / CA と利用時の設定を分けて確認する。クラウド API と
  Web はそれぞれ明示した proxy または直接接続を使い、環境変数の proxy に頼らない。
  Local は proxy を使わず、LAN の HTTP は平文。利用時の独自 CA 登録 UI はない。
  オフラインでのインストール成功は、推論のオフライン動作や利用時の接続成功を意味しない。

接続方式・Web・データ共有: [README](../README.md)、[Security model](../SECURITY.md)。

## 4. 権限・状態・キーの寿命

- [ ] 読み取りと書き込みを必要な既存フォルダーだけに許可し、重要な原本と出力先を分ける。
  read / write は独立し、deny が優先する。アプリ・状態フォルダーは常に対象外。
  この制限は、同じ Windows ユーザーで動く別プロセスを隔離する OS サンドボックスではない。
- [ ] 既定の状態フォルダー `%LOCALAPPDATA%\AgentWorkbench` を使う。
  Windows では継承アクセスを外し、現ユーザー / SYSTEM に権限を付けるが、手動指定した
  状態フォルダーの既存の明示許可をすべて削除するわけではない。
- [ ] `settings.json` のパス・接続先・モデル名・方針は秘密を含み得る管理情報として扱う。
  キーは専用欄か指定の環境変数を使い、ラベル・URL・方針などの保存欄に貼らない。
  アプリは専用欄のキーを設定ファイルに保存しない。環境変数の保存元は別途管理する。
- [ ] 会話・履歴・入力したキーはサーバープロセス内で保持される。マスキング用に認識した
  旧キーも通常はプロセス終了まで残り得て、直ちに安全消去できる保証はない。
  タブを閉じてもサーバーは止まらない。終了前に必要な報告・保存記録を個別に保存する。
  既に保存した作業ファイル、ブラウザーダウンロード、クリップボードの内容は別に残る。

詳しい境界と保持条件: [Security model](../SECURITY.md) の「Credentials and state」、
[README](../README.md) の「思考表示と保存」。起動 URL や認証 Cookie も共有しない。

## 5. 操作の限界と受け入れ確認

- [ ] モデルは任意コマンド・プロセス起動・パッケージ導入を行えないことを理解した。
  これはセットアップやアプリ自身が処理を実行しないという意味ではない。
  セットアップの Python / pip、権限設定、固定の GPU 監視等の補助処理は存在する。
- [ ] `Setup.cmd --help` は説明表示のみ、`--check` は限定的な前提確認。
  `Setup complete` は導入の確認で、会社の許可や利用先との通信成功を証明しない。
  「モデル一覧を確認」も一覧取得だけで、推論・ツール動作・品質の確認ではない。
- [ ] 対象 PC の実行制御、proxy / CA、接続先、許可したデータの扱いについて、
  組織に必要な受け入れ確認と未解決事項を記録する。CI はその代わりにならない。

検証した範囲と証拠: [Validation scope](VALIDATION.md)、[検証記録](evidence/README.md)。
過去の合格は記載されたコミットだけの記録で、別のソース版や会社 PC の認証ではありません。
