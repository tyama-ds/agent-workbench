# Copilot Agent の JSON 作業要求

0.1.1.dev38 では、設定から追加される専用の Copilot Agent が操作を必要とする場合、AWB が最初の実タスクと同じ送信内で次の役割を説明します。

> 実際の操作はユーザーの PC 上の Agent Workbench が行います。あなたは次に必要な作業要求を、指定した JSON で返してください。実行結果が届くまで、実行済みと報告しないでください。

操作一覧・引数の形式・返答例も渡します。別の準備用推論や、形式を直させるための AWB の自動再送は追加しません。各担当の会話 ID と履歴、既存の権限・時間・回数制限を使います。利用者がこの説明を毎回入力する必要はありません。通常の Local / OpenAI / Anthropic 接続と、操作を使わない会話要約は従来の形式です。

## 返答と実行

操作要求の例です。`read_file` がその時点で許可された操作一覧にある場合だけ受理されます。

```json
{"awb_protocol":"copilot-json-v1","kind":"requests","requests":[{"tool":"read_file","args":{"path":"report.txt"}}]}
```

操作が不要な回答は次の形式です。回答文は、作業完了や権限の証明にはなりません。PM の完了条件などは引き続き AWB が検査します。

```json
{"awb_protocol":"copilot-json-v1","kind":"final","text":"確認した結果を報告します。"}
```

実際の返答ではコードフェンスや前置きを付けず、JSON 全体を一つ返します。AWB は版・全項目・全操作名・引数の構造を検査します。一つの返答は最大1 MiB、操作要求は1〜64件です。既存のツール回数上限は別途適用されます。不正な JSON、重複キー、未知の操作、途中で切れた回答、通常文との混在は、その回答の操作を一件も実行せずエラーにします。引数の詳細・ファイル範囲・承認などは既存の実行側でも検査します。

受理後は AWB が呼び出し ID を割り当て、実行結果と対応させて次の送信に含めます。元の返答と変換後の要求を区別して保持し、会話量の計測にも実送信と同じテキスト変換を使います。

## Bridge との境界

通信は既存の Chat Completions 接続です。専用モードでは API の `tools` を空にし、AWB の操作仕様を本文へ含めます。Copilot にネイティブのツール機能があるとは扱いません。Bridge が返答を独自にネイティブ `tool_calls` へ書き換えた場合も、その回答は拒否します。

Bridge 自身の再送・言い直し・表示上限は AWB の HTTP 再試行とは別です。この変更は既存 Bridge の設定を変更しません。AWB の HTTP 一回を、Copilot 画面への送信一回と同一視しないでください。Bridge の版や応答変換によっては対応しないことがあります。

ローカルの自動検証では合成応答を使います。実際の Copilot アカウントでの形式遵守、認証の継続、作業の完走は別途確認が必要です。
