履歴の保持・終了について
担当者ごとに最新20件の報告（各24,000文字まで）・64件の保存記録・200件のログを保持します。上限を超えた記録や本文は、表示用の履歴から省略します。必要な報告・保存記録は早めに選んで .txt 保存し、ブラウザーでダウンロード完了を確認してください。
ブラウザーのタブを閉じたり再読み込みしても、サーバーと実行中の作業は停止しません。画面の「停止」は選択したチームだけを止め、履歴は保持します。
起動したコンソールを閉じるか Ctrl+C でサーバーを終了すると、すべてのチームの履歴と入力した API キーは失われます。設定ファイルは残り、環境変数のキーは次の起動時の環境を使います。未送信の下書きや、ブラウザー終了後の再接続は保証しません。
保存済みの作業ファイルは、チームの停止やサーバーの終了では削除しません。保存記録は保存時点の情報で、現在のファイルの存在・内容は未確認です。

新しい作業

          

          
「チームを開始」を押すと、この画面の選択と開始時の保存済み設定で新しいチームを作成します。過去の会話・成果・設定は引き継ぎません。必要な内容は確認して追記してください。表示中の伏せ字はそのまま使い、復元しません。改行は入力欄の形式（LF）にそろえます。空白やその他の文字は変更しません。

文章の整理や、許可したファイルの読み書きを依頼できます。コマンド・ビルド・テストは実行できません。

            
依頼例と必要な設定

              
文章だけで始める
例：次のメモを、決定事項・担当・期限に整理し、不明点を列挙してください。続けてメモ本文を貼り付けます。
使うモデルの設定が必要です。ファイルの許可や Web の設定は不要です。作業者の上限を 0 にすると PM だけで作業します。

              
許可したファイルを使う
例：指定した入力フォルダーの資料を要約し、指定した出力フォルダーに summary.docx を作成してください。元資料は変更しないでください。
既存フォルダーの絶対パスを依頼に書き、入力先の読み取り・出力先の書き込みを設定で許可します。UTF-8 テキストと対応する .docx / .xlsx / .pptx を扱えます。フォルダー作成・ファイル削除はできません。コードを編集した後のビルドやテストは、ユーザーが実行してください。

              
公開 Web の資料を調べる
例：指定したテーマを公開 Web で調べ、参照した URL と要点、確認できなかった点をまとめてください。
設定で Web を有効にし、検索サービスの接続先と必要なキーを設定します。検索とページ取得の利用状態は「開始前の確認」で確認してください。ページ取得は公開 HTTP(S) テキストが対象で、ログインや JavaScript の実行はできません。

WORKSPACE SETTINGS
CONFIGURATION
作業環境を整える。
使うモデル、アクセスできる場所、実行の上限を設定します。

        

          
キーはこの起動中だけ保持し、設定ファイルには保存しません。同じ保存済みプロファイル（検索キーは同じ検索設定）を使うすべてのチームの次のリクエストに反映されます。送信済みのリクエストは変わりません。セットするだけでは接続確認・自動再試行は行いません。

          

          
モデルのプロファイル
同じサービスに複数のモデルを登録できます。モデル名は自由に指定できます。

          
ファイルへのアクセス
絶対パスを1行に1つ入力してください。拒否する場所は許可より優先されます。

          
Web 検索・ページ取得
検索サービスの接続先と、必要な環境変数を指定します。
未入力のままなら、指定した環境変数を使用します。

          
ローカルモデルの実行制御
人数に関わらず、Local 全体のリクエスト数・待ち時間を制御します。リクエスト上限は、プロファイルの設定値にも適用されます。
GPU のしきい値はリクエスト開始前の確認です。モデルの VRAM 割り当て量を強制的に制限する機能ではありません。確認対象はこの PC の GPU です。別の PC にある Local API では使用できません。

          
作業の上限
自動連携、呼び出し回数、時間、コンテキスト、出力の予算を設定します。変更は新しい作業に適用されます。

          
共通の作業方針
PM と作業者に共有する指示です。作業を始める前に確認・編集できます。
