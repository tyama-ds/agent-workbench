# Agent Workbench

[検証範囲](docs/VALIDATION.md)・[開発履歴](docs/DEVELOPMENT_LOG.md)・[過去の PR 検証記録](docs/evidence/README.md)。各 CI・画面確認の結果は記載されたコミットに限ります。

[2026-10-09 の統合内容と検証](docs/INTEGRATION_REVIEW.md): Python を同梱しないソース版として、セットアップ・操作画面・復旧・会話要約を統合しています。

Windows 11 で動く、Local LLM・OpenAI・Anthropic のためのエージェント作業アプリです。PM が作業者を作り、役割を割り当て、メールで相談し、結果を受け取って作業をまとめます。同じ API を使う役割別チームと、異なる API を使う混成チームの両方に対応します。

Codex CLI / Claude Code / WSL / Docker / Microsoft Office のインストールは不要です。LLM サーバーそのものは別途用意してください。ORRERY のソースや素材は使用せず、新規に実装しています。

PMからの委任では、元の依頼を全ワーカーが共通で参照します。同僚の連絡待ちには専用の待機操作を使い、PMは現在の正式報告に対して承認または具体的な修正依頼を返せます。「委任必須」ではPMの承認前に最終完了にしません。詳しくは [チーム連携と確認](docs/TEAM_COLLABORATION.md) を参照してください。

## Windows で起動

社内導入の確認項目は [IT 向けチェックリスト](docs/IT_REVIEW_CHECKLIST.md) にまとめています。

必要なもの: Windows 11、承認済みの通常版 **64-bit CPython 3.11〜3.13**（3.13 推奨）、Edge または Chrome。

1. ソース ZIP を、自分が書き込めるローカルフォルダーにすべて展開します。
2. **`Setup.bat` をダブルクリック**します。`Python path:` に、インストール済みの `python.exe` のフルパスを貼り付けて Enter を押します。続いて会社指定のプロキシ URL と、必要なら PEM CA 証明書のパスを入力し、`Setup complete` を確認します。プロキシ・証明書の入力は空欄で既存設定を使えます。エクスプローラーの「パスのコピー」で付く引用符もそのまま使えます。Python のパスを空欄で Enter を押すと中止します。
3. **`Launch.bat` をダブルクリック**します。次回からはこれだけで起動でき、Python のパス入力も不要です。起動したコンソールで Ctrl+C を押すと停止します。

**更新時は同じアプリフォルダーを使えます。** AWBを終了し、今回の公式ソースZIPの中身を既存フォルダーへ上書きして、`.venv` は残します。`Update.bat` → `Update complete` → `Launch.bat` の順で起動してください。既存のPython環境を使うため、Pythonパスの再入力は不要です。設定・保存済み履歴・同じ場所を指すショートカットも引き継ぎます。ソースのダウンロードや展開は自動では行いません。初回導入・フォルダー移動・壊れた環境の作り直しには `Setup.bat` を使います。詳しくは [更新と引き継ぎ](docs/WINDOWS_SETUP.md#更新と引き継ぎ) を参照してください。

通常のセットアップ・起動に PowerShell、管理者権限、Git、ビルドツールは不要です。**Python は同梱しません。組織の認可を受け、アプリとは別にインストールしてください。** アプリが Python 本体をダウンロード・インストールすることはありません。社内ポリシーによる実行禁止やセキュリティ警告を回避する設定は行いません。

通常はこの2つの BAT だけを使います。コマンド入力や環境変数の設定は不要です。既に `WORKBENCH_PYTHON` が設定されている場合だけ、そのパスを使って入力を省略します。従来の `Setup.cmd` / `Launch.cmd` も互換用に残しています。

デスクトップから起動したい場合は、`Create-Shortcut.bat` をダブルクリックします。Agent Workbench 専用アイコンのショートカットを作ります。同じ展開先を指す既存ショートカットはアイコンだけ更新し、別の展開先を指す同名リンクは上書きしません。アイコンはブラウザーのタブにも表示されます。ICO 原本は `static/agent-workbench.ico`（16〜256 px の9サイズ）、PNG は `static/agent-workbench.png` です。BAT ファイル自体のアイコンは変わりません。

Python の指定前でも `Setup.bat --help`（`-h` / `/?` も可）で手順とオプションを確認できます。ヘルプは最初の引数として単独で指定し、ほかのオプションは別の実行に分けてください。Python の起動、インストール、通信は行いません。

ダブルクリック時に入力したプロキシ・証明書は今回のセットアップだけに使い、保存しません。プロキシ認証（407）や PAC / SSO の自動設定には対応していないため、該当する場合は IT 担当に確認してください。

コマンドプロンプトから診断・プロキシ・オフラインインストールも指定できます。引数を指定した場合は追加のプロキシ・証明書入力を求めません（`--interactive` を指定した場合を除く）。

```bat
Setup.bat --check
Setup.bat --proxy "http://proxy.example.local:8080"
Setup.bat --wheelhouse "C:\Approved Packages\wheelhouse"
```

Python のパスは実行時に貼り付けます。上のプロキシは例です。会社の指定値を使ってください。`py` / `python` の自動探索は行いません。証明書は `--certificate "C:\Certificates\company-ca.pem"` で指定できます。通常モードは既存 pip / proxy 設定を引き継ぎます。パッケージはハッシュを確認した wheel のみ利用し、依存のソースビルドや TLS 検証無効化は行いません。

`0.1.1.dev10` では、失敗したセットアップ段階と対処先を表示します。別の Python / インストール先へ切り替える pip 設定と TLS 検証を省く設定は、依存インストール前に停止します。通常の社内 proxy / CA / ミラーは引き続き使えます。詳しくは [Windows セットアップガイド](docs/WINDOWS_SETUP.md) の「どの段階で止まったか」を参照してください。

既定ポートは `8818`。二重起動は既に起動中であることを表示します。既存のブラウザー画面を使ってください。別アプリが使っている場合は `Launch.bat --port 8820` で起動してください。アプリはソースフォルダーを利用するため、セットアップ後にフォルダーを移動しないでください。

**詳しい手順・Python の指定・社内 CA・オフライン wheel の準備・エラー対処は [Windows 11 セットアップガイド](docs/WINDOWS_SETUP.md) を参照してください。**

## 最初の設定

1. **設定 → モデルのプロファイル**で接続先、モデル名を入力して保存します。モデル名は利用中のサーバーやアカウントで有効なものを入力してください。固定の推奨モデル名は埋め込んでいません。
2. クラウド API キーは専用のパスワード欄へ直接入力し、「キーの保存方法」を選んでセットします。既定は「この起動中のみ」です。「このWindowsユーザーに暗号化保存」を選ぶと、同じPC・Windowsユーザー・保存先で再起動や更新後も利用できます。環境変数 `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` も利用できます。値は再表示せず、設定ファイルや設定バックアップには含めません。
3. 作業用フォルダーをエクスプローラーで作成し、**読み取りを許可する場所**と**書き込みを許可する場所**に絶対パスを登録します。例えば `C:\AgentWork\documents`。アプリ自身のフォルダーや状態フォルダーは常に拒否されるので、作業用に別の場所を使ってください。
4. **＋ 新しい作業**を開き、依頼、PM、作業者に許可するプロファイル、作業者数を選んで開始します。

最初は、メモ本文を貼り付けて「決定事項・担当・期限に整理し、不明点を列挙してください」と依頼できます。文章だけの作業には手順3のフォルダー登録や Web の設定は不要です。作業者の上限を `0` にすると PM だけで作業します。モデル接続先の設定や必要なキーは、文章だけの場合も必要です。

新しい作業の入力欄の下に、使える操作と実行できない操作を表示します。「依頼例と必要な設定」を開くと、文章・ファイル・Python・公開 Web・Selenium の依頼例を確認できます。ファイル例は実際の既存フォルダーの絶対パスに置き換え、必要な読み取り・書き込みを個別に許可してください。Web 例には検索サービスの設定が必要です。Python は設定で既存の `python.exe` とライブラリの場所を指定し、有効にすると隔離環境で実行できます。**任意のシェルコマンドや Python からの子プロセス起動には対応しません。** ブラウザー操作は別途有効にする Selenium 専用ツールで行います。開始前の確認は設定の確認であり、依頼の達成やモデルの品質を保証しません。

「モデル一覧を確認」は `/models` の取得だけです。推論・ツール動作は未確認です。有料リクエストの成功を保証するチェックではありません。

| 接続方式 | API ベース URL の例 | 使用する API |
| --- | --- | --- |
| Local / OpenAI 互換 | `http://127.0.0.1:11434/v1` または実際のポート | `/chat/completions` |
| OpenAI | `https://api.openai.com/v1` | `/responses`、`store:false` |
| Anthropic | `https://api.anthropic.com/v1` | `/messages` |

Local サーバーには OpenAI 互換の **JSON tool calling** が必要です。通常のチャットだけに対応するサーバー、テキスト中にツール名を書くだけのモデルでは自律操作できません。Qwen 等を使う際は、サーバー側の chat template / tool parser も対応させてください。生成されたコードや JSON 風の文章を勝手に実行するフォールバックはありません。

Local は loopback と、数値で指定した RFC1918 / IPv6 ULA の LAN アドレスに対応します。環境変数を含め、プロキシは常に使いません。LAN の HTTP は平文通信です。社内ネットワークで必要な認証・HTTPS は推論サーバー側で設定してください。

Local / OpenAI 互換（`kind: local`）のエージェント推論には `X-Conversation-Id: <run ID>/<agent ID>` を送ります（ASCII 英数字と `-_./:` 以外を `_` に置換し、先頭128文字まで）。OpenAI / Anthropic や、要約などIDを渡さない呼び出しには送りません。
対応する中継はこのIDで会話を識別でき、未知のヘッダを無視する他の接続先には影響しません。推論ペイロードは変更しません。

## Copilot-agent mode

「設定 → Copilot-agent mode」で、既存の `copilot-bridge` フォルダーと、その依存ライブラリを利用できる `python.exe` の絶対パスを指定します。API ベース URL の既定は `http://127.0.0.1:8800/v1`、モデル名は `copilot`、起動待ちの上限は600秒です。既定はオフで、自動インストールは行いません。

フォルダーとPython欄を空にした場合は、隣接する既存の `copilot-bridge`（`for_eigyo/copilot-bridge` / `for-eigyo-pdf-lingua/copilot-bridge` も対象）と導入済みのPython環境を探します。見つからない場合は場所を指定してください。以前から `copilot-agent` というIDの通常プロファイルがある場合、オフでは引き続き利用できます。オンにする前に、そのIDを別名に変更してください。

オンにして保存するとBridgeの準備をバックグラウンドで始めます。「起動中」と「接続可能」は別に表示し、失敗時は理由を表示します。Edgeが開いた場合は必要に応じてサインインしてください。新しい未入力の作業では `Copilot Agent` をPM・作業者の初期選択にし、明示した別のプロファイルや入力済みの下書きは保持します。既存のモデル設定を書き換えず、追加PMの候補にも表示します。Bridgeが利用できない場合に別モデルへ自動で送り直す機能ではありません。

Bridgeは公式Copilot APIではなく、既存のM365チャット画面を操作するChat Completions互換の仲介です。オンにしてCopilot Agentを選ぶと、依頼・会話・ファイル内容・ツール結果の送信先は、そのCopilotアカウントと契約になります。AWBが管理起動するBridgeは専用のEdgeプロファイルを使い、`--log-dir ''` によりローカルの全往復ログを無効にします。既に起動済みのBridgeを再利用する場合は、そのBridgeの設定やログ設定を変更しません。Bridgeのブラウザーと、AWBのSeleniumツールのブラウザーは別です。

AWB側ではLocal / Chat Completionsとして接続します。「Copilot の同時リクエスト数」で、通常のLocalモデルとは別に1〜16件の送信枠を設定できます。既定は1件で、待ち時間・リクエスト時間はLocal設定を使います。同じCopilotを複数のワーカーに割り当てた場合も会話IDと履歴は別です。実際に並行処理できる数はBridgeのウィンドウ数と接続先の処理能力にも依存し、この設定でBridgeのウィンドウを自動増設することはありません。作業予算・ツール権限は維持します。この専用接続先は外部のCopilotを利用するためローカルGPUの確認を適用せず、AWBは失敗したHTTP要求を自動再試行しません。Bridge内部の再送・言い直しとは別です。他のLocalプロファイルの設定は変えません。「接続可能」はHTTP応答でBridgeを識別できた状態です。サインインの継続、推論・ツール動作、調査内容の正確さを保証するものではありません。

0.1.1.dev38 から、専用のCopilot Agentには「実際の操作はユーザーのPC上のAWBが行うので、作業要求を指定のJSONで返す」というルールを、最初の実タスクと一緒に送ります。操作一覧と返答例も自動で添え、AWBが返答全体を検査して既存の権限内で実行します。準備用の追加推論は不要です。通常の文章や壊れたJSONを操作として拾う機能ではありません。詳細は [Copilot Agent の JSON 作業要求](docs/COPILOT_PROTOCOL.md) を参照してください。

起動エラー後は、設定画面の「再接続」を押して明示的に再起動を要求できます。作業の実行中や未保存の設定がある間は再接続できません。

## チームの使い方

同じ Local プロファイルだけを PM・作業者に指定すると、単一モデルが別々の会話と役割を持ちます。OpenAI の PM に Local と Anthropic の作業者を許可すると、PM はその範囲で担当と API を選べます。作業者同士の連絡も同じチーム内で行えます。

PM は既定で1人です。「複数の PM で分担する」を開くと、同じ作業に最大16人まで配置できます。同じプロファイルを繰り返し選んでも会話・IDは別になります。PM 1 が最初の分担を調整し、各PMが自分のsubagentを作成・管理します。作業者数の上限は **全PMの合計で、PM本人を含みません**。Local推論の同時数、実行時間、モデル・ツール・自動連携回数の予算も共有します。すべてのPMと作業者が終わるまで作業全体は完了しません。

依頼例:

> 読み取りを許可したフォルダーの資料を整理してください。調査担当とレビュー担当に分担し、通常の判断はチーム内で相談してください。許可した出力フォルダーに summary.docx と tasks.xlsx を作成し、読み直して検証してください。元資料は変更しないでください。目的が変わる判断だけ質問してください。

作業者の完了通知やメールで PM / 相手の次のターンが自動的に始まります。`ask_user` の質問は人が回答するまで待機し、仲間のメールでは解除されません。作業方針は設定から全文確認・編集できます。

「PMの委任方針」は設定画面と新しい作業のスライダーで調整します。設定画面は次の作業の既定値、新しい作業の値はそのチームにだけ適用します。

- **PM中心**：PMが必要に応じて自分で作業・委任します。
- **委任優先**（既定）：PMは仕事を分解し、指定人数を目安に異なる担当を割り当て、結果を確認・統合して報告するよう指示されます。人数は目安です。
- **委任必須**：各PMは指定人数への委任と、作業者の現在の正式な完了報告を受け取る必要があります。委任や報告が不足したまま実作業へ進むこと、文章だけで完了扱いにすることを防ぎます。報告後の確認・統合・保存はPMが行えます。実装が確認するのは手順と報告の受領であり、内容の正しさや統合の品質は別途確認が必要です。

「PM1人あたりの委任人数」は1〜16人です。委任必須では「PM数 × 委任人数」以上の作業者枠が必要で、足りない場合は開始前に表示します。PMだけで作業する場合は作業者上限を0にし、委任必須以外を選びます。PMは `wait_for_workers` で作業者の報告を待てるため、待機だけの推論を繰り返す必要はありません。必要な質問はどの方針でも行えます。人数を増やしても呼び出し回数・時間・自動連携の予算は増えません。

同じモデルを3人に使う場合は、作業者用プロファイルでそのモデルを1つ選び、作業者上限と委任人数を3にします。同じプロファイルの登録を3つ作る必要はありません。GPTを含むクラウドAPIは各担当の履歴で別々にリクエストします。LocalやCopilotの同時リクエスト数を1にしていても会話は複数持てますが、推論の送信は順番待ちになります。接続先の利用上限は引き続き適用されます。

固定の参照資料を使う順番付き作業では、PMの承認時に、各手の実際の先行出力・提出内容・参照項目を照合します。不一致の承認では次の手に進みません。各手の参照情報は最終報告まで保持し、画面では照合済みの事実とPMの未検証コメントを分けます。資料との一致は一般的な意味の正しさやモデルの理解を保証しません。詳しくは[監査記録の見方](docs/OBSERVABILITY.md)を参照してください。

### チームのコックピット

同じワークの全員で相談を共有する「ワーク掲示板」のプロトタイプもあります。設定でONにして保存すると、次に開始するワークの「掲示板」から使えます。PM・ワーカー・人が投稿でき、返信先を引用できます。既定はOFFで、正式な報告や個別メールは従来どおりです。使い分けと今回の範囲は [ワーク掲示板の企画・操作案](docs/WORK_BOARD.md) を参照してください。

中央のネットワークでPM・作業者の状態と担当を見渡し、丸をクリックして概要を固定し、「担当ログを開く」で右側に依頼、最新の公開処理記録、質問、作業ログ、成果・保存記録を表示します。親子の線は担当関係、方向付きのメール線は表示範囲に残る実際の送信を示します。通信線やメールから相手とやり取りを絞り込み、選んだ担当へ人として追加指示を送れます。狭い画面ではネットワークと担当者の詳細を切り替えて使います。

連携図では、丸ひとつがPMまたはワーカーです。丸にマウスを重ねるかキーボードでフォーカスすると、担当・状態・最新記録を表示します。クリック／Enterで固定し、Escapeまたは閉じるボタンで解除できます。「担当ログを開く」で全文へ進みます。ドラッグ、背景の移動、拡大・縮小、全体表示も使えます。配置と固定はワークごとにブラウザー内だけで保持し、指示や担当関係は変えません。

動いているリングは公開状態が「作業中」の担当を示します。新しい実メールの送信受付では水色の粒が送信元から宛先へ流れ、モデルの会話への取り込みでは宛先に金色のリングが短く広がります。送信受付を既読とせず、取り込みも理解・完了の保証ではありません。履歴を開いた際や再接続時は過去の通信を再生しません。「動き」ボタンで停止でき、OSの動きを減らす設定も尊重します。詳細は [動的ネットワーク表示](docs/DYNAMIC_NETWORK.md) を参照してください。

状態と「最新の記録」は別の情報です。最後に記録したツールが今も実行中とは限りません。メールのキュー受理と会話への取り込みも分けて表示し、取り込みを理解・統合・作業完了とは扱いません。表示できる通信は保持されているイベントの範囲だけです。担当者やチームを切り替えても、人の未送信入力を別の相手へ自動送信しません。

### チーム内メール

PMから任意の作業者へ、作業者から別の作業者やPMへ、同じチーム内で直接相談できます。PMを経由する必要はありません。エージェントの `send_message` は任意の件名と1〜16人の明示宛先に対応します。従来の単一宛先も使えます。複数宛先でも送信先ごとに自動連携予算を1回消費し、残数や宛先の状態を先に検査します。表示された送信記録を確認せず、同じ依頼を自動的に再送しないでください。

画面から入力した内容の差出人は人です。PMや作業者の発言には偽装しません。仲間からの相談を人の承認とみなしたり、質問待ちを解除したりすることはありません。正式な作業完了には引き続き本人の `finish_work` が必要です。

| 設定 | 意味 |
| --- | --- |
| 作業者の上限 | 1つの仕事の全PMで共有する worker 数。PM は含まず、既定3人・最大16人。0ならPMだけ。既存 worker は追加依頼で再利用 |
| 自動連携回数の上限 | 1つの仕事のチーム全体で共有する委任・連絡回数。既定24回、0〜1000回で設定。0なら自動連携なしでPMが作業 |
| Local 同時リクエスト数 | 全チーム・通常の Local プロファイル合計の推論枠。例: worker 4人、推論枠1なら順番に推論 |
| Copilot 同時リクエスト数 | 通常の Local とは別の送信枠。実並列数はBridgeのウィンドウ数とサービス側の上限にも依存 |
| キューの待機上限 | 推論枠・開始間隔・GPU 状態を待つ時間の上限 |
| リクエスト上限 | API 応答を待つ時間。Local はプロファイルと共通設定の小さい方 |
| 開始間隔 | Local リクエストの開始間に必要な秒数 |
| 再試行 | Local の HTTP 429 / 503 だけを指定回数まで再試行。接続断による曖昧な処理の再実行はしない |
| 実行予算 | チーム全体のモデル呼び出し数・ツール数・時間、および会話長・出力・各エージェントのターン数 |

**設定 → 作業の上限 → 自動連携回数の上限**から変更できます。新しい作業には設定した上限が適用され、作業画面に「自動連携 使用回数 / 上限」を表示します。既存の設定ファイルに項目がなくても、24回を適用します。

作業者の作成と最初の委任、エージェント間のメール、作業者からPMへの自動完了・エラー通知が、正常に届くたびに各1回を消費します。人の依頼・回答、通常のモデル呼び出しやファイル操作、失敗した連絡は数えません。上限後は新しい委任・連絡を停止し、開始済み・待機中の作業は続行できます。上限で連絡が止まった場合は画面に表示し、自動でチーム全体を完了扱いにしません。PM中心・委任優先では、人が追加指示を送ってPM単独で仕上げることはできますが、回数はリセットされません。委任必須では、人の文章で不足するworker報告を代用できません。必要な報告を受け取れない場合は、新しい作業で人数・方針・予算を見直してください。上限を変更して連携を続ける場合は作業を停止し、設定を保存して新しい作業を開始してください。

「停止」は新しい操作を止め、実行中のローカルファイル操作の終了を待ちます。外部 API のサーバー側推論の中止や課金取り消し、既に保存したファイルの巻き戻しは保証しません。実行時間の上限到達後は新しいツール操作を始めませんが、開始済みの安全なファイル保存は完了を待ちます。 `0.1.1.dev17` では、他のファイル操作の終了を待っている間に期限に達した場合も、待機していた操作を開始しません。既に消費した呼び出し回数や保存記録は維持します。

`0.1.1.dev15` では、ツールの予期しない例外や結果の生成エラーで、そのエージェントのターンを停止します。同じ応答に含まれる後続の操作は実行せず、会話には各操作の結果を残します。先に成功した保存記録は保持しますが、エラーになった操作もファイルを保存済みの場合があるため、保存記録とファイルの現状を確認してから追加指示を送ってください。自動で同じ操作を再実行せず、既存の権限・予算を満たす場合だけ続行できます。通常の引数・権限エラーは引き続きモデルに返し、修正を促します。

`0.1.1.dev16` では、応答に未完了・失敗の情報がある場合、その応答を最終報告にせず、含まれるツールも実行しません。Local の `finish_reason` と Anthropic の `stop_reason` は、非ストリーミング応答で認識できる終了理由が必要です。これらを省略したり `null` にしたりする互換サーバー・プロキシはエラーになります。接続先が終了理由を返す設定・実装か確認してください。OpenAI Responses の省略可能な状態項目は引き続き使えますが、明示された未完了・エラー情報を無視して続行しません。

Local が `refusal` に返した拒否の説明は、通常の回答と同じ「モデルの報告」で確認でき、追加指示時の会話にも保持されます。拒否の説明とツール呼び出しが矛盾する応答は停止します。空の正常終了を一律にエラーにせず、拒否や空の応答を実作業の成功の証拠にはしません。先の保存記録と消費済み予算は維持し、自動で再試行しません。

## GPU / VRAM

NVIDIA の `nvidia-smi` から **この PC の GPU 全体**の使用 VRAM と使用率を取得し、しきい値を超えている間は新しい Local リクエストの開始を待ちます。GPU 番号、確認間隔、待機上限、取得不能時に拒否するかを設定できます。各しきい値の `0` はその条件を無効にします。

**これは開始前の監視です。VRAM / GPU 使用量のハード上限ではありません。** リクエスト開始後の割り当てを止めたり、外部推論サーバーの GPU メモリを解放したりする機能はありません。モデル常駐分も使用 VRAM に含まれるため、常駐量より小さいしきい値では開始できません。厳密な割り当て制限は推論サーバー側で設定してください。

LAN 上の Local サーバーでは、この PC の GPU 値を代用できないため GPU 監視を有効にできません。AMD / Intel の監視には未対応です。推論の同時数や待機上限は GPU 監視を無効にしても有効です。

## Web 検索とプロキシ

既定では無効です。検索方式の標準は API キー不要の DuckDuckGo です。明示的に設定した SearXNG JSON API も使用できます。検索方式を変更しても、Web 検索・ページ取得は自動で有効になりません。

- SearXNG: 使用するサーバーの `/search` URL。JSON 出力が有効なサーバーが必要です。LAN 内でも HTTPS が必要です。HTTP の例外は `localhost` / `127.0.0.1` / `[::1]` のみです。
- DuckDuckGo: 接続先は `https://html.duckduckgo.com/html/` に固定です。公開 HTML の検索結果を取得します。API キーや検索用の環境変数設定は不要です。アクセス制限や確認画面が表示された場合は、結果を取得できないことがあります。
- 検索用プロキシ例: `http://127.0.0.1:8080`。**検索と検索後のページ取得の両方**に適用されます。失敗時に直接接続へ切り替えません。
- OpenAI / Anthropic にもプロファイルごとの明示プロキシがあります。検索の設定とは独立しています。

以前の Brave 設定と、接続先が空の未使用 SearXNG 設定は、読み込み時に DuckDuckGo へ移行します。有効・無効やプロキシ、時間・サイズ上限は維持します。保存済みファイルを書き換えるのは、設定画面で保存したときです。

HTTP(S) プロキシに対応します。SOCKS、PAC、URL に埋め込んだ認証情報、独自 CA の登録 UI は未対応です。Local はこれらの設定の影響を受けません。Web の取得対象は公開 HTTP(S) テキストのみで、JavaScript は実行しません。内部・メタデータアドレスや危険なリダイレクトを拒否します。明示した SearXNG 検索サーバーだけは内部の接続先も利用できます（LAN 内も HTTPS が必要）。

### 大量のデータを調べる作業と共有予算（0.1.1.dev37）

モデル・ツールの使用回数と上限・残り回数、経過時間と残り時間を作業画面に表示します。PM と全作業者で共有する枠で、会話の要約もモデル回数を使います。表示はサーバーで観測した時点の値です。保存履歴には保存時点の値を表示し、古い版で記録していない上限や残時間は補いません。

実行時間、モデル呼び出し回数、ツール回数、担当のターン数の上限と、モデル API の応答待ちタイムアウトを分けて表示します。`Provider request timed out; no automatic retry` はモデル API の待ち時間切れです。入力の大きさ・モデルの処理速度・通信状況のどれが原因かを、この文言だけで判定することはできません。自動再試行や上限の自動増加は行いません。

Web 取得では、長い本文や JSON 全体を一度にモデルへ渡さず、上限付きのプレビューと構造を返します。モデルは `web_read` で、取得済みデータの必要な項目・配列の範囲を読み直せます。これは同じ取得時点のデータで、追加の通信はしません。更新された情報が必要なら新しく取得します。保存する本文は最大20万文字、作業ごとの一時保持は最大8件・2MiBで、上限を超えると古いデータを除外します。履歴や設定バックアップには、この一時データ全体を保存しません。

日付と値の対応を保つため、JSON の空欄・`null`・配列の位置を勝手に詰めません。省略や保持対象外の範囲は未確認のままです。例えば「関東地方の明日の天気をExcelにまとめる」なら、対象地域・日付・必要項目を先に決め、必要な情報がそろったところで統合・保存・読戻しへ進む方針を PM と作業者へ伝えます。特定サイトの API、実際のモデルでの完走、Selenium や Python による取得量まで保証する機能ではありません。

### ページ本文の文字コード（0.1.1.dev8）

UTF-8 に加え、宣言付きの Shift_JIS / Windows-31J（CP932）、EUC-JP、ISO-2022-JP、Windows-1252、ASCII、ISO-8859-1、UTF-16LE/BE に対応します。HTML の ASCII / Latin-1 系ラベルは Windows-1252 として扱います。取得結果には、実際のデコーダー `encoding` と選択根拠 `encoding_source` を本文より前に含めます。

BOM、HTTP の charset、先頭の HTML meta（最初の1,024バイト内）の順で選びます。meta の検査は script / style / title / textarea / template 等に達すると止め、その後の宣言は使いません。宣言がない通常のテキストは UTF-8 と仮定し、`encoding_assumed: true` を返します。XHTML は HTML meta ではなく XML 宣言、JSON は常に UTF-8 を使います。JSON の先頭 UTF-8 BOM は除去します。

選択した文字コードで読めない場合や未対応・曖昧な宣言は、置換文字や別の文字コードで推測せず、説明付きのエラーにします。元のページの誤りと断定するものではありません。明示した対応 charset のあるページ、または UTF-8 版を使ってください。ブラウザーと完全に同じ文字コード推定・HTML/XML 解析ではなく、正しい charset 宣言そのものも保証しません。最大20万文字の本文と省略有無を返し、取得内容は引き続き未信頼の資料として扱います。

## ファイルと Office

| 形式 | 対応する操作 | 制限 |
| --- | --- | --- |
| フォルダー | 許可した書き込み範囲内の子フォルダー作成（`create_directory`） | 1回につき新規32階層まで。既存フォルダーはそのまま。削除・移動なし |
| 名前検索 | `search_paths` でファイル・フォルダー名を再帰検索 | 読み取り許可範囲のみ。部分一致、種類・深さ・件数指定。本文検索は `search_text` |
| UTF-8 テキスト | 読む、検索、作成、置換、SHA-256取得 | 既知の文書・バイナリー形式、非 UTF-8、NUL・バイナリー制御文字への上書き不可 |
| `.docx` | 段落・表の読み取り、作成、段落・セルの編集 | Word COM / マクロ / OLE / 外部参照なし |
| `.xlsx` | シート・セル範囲の読み取り、セル更新、シート作成 | 許可した通常関数のみ。数式の再計算エンジンなし |
| `.pptx` | スライドテキストの読み取り、作成、既存テキストの編集 | PowerPoint 全機能・描画の完全再現ではない |

読み取り・検索は UTF-8 と NUL の有無で判定します。破壊的なテキスト操作（作成・上書き・部分置換）は追加の保護を行います。PDF、Office、OpenDocument、主要な画像・圧縮形式、および WAV/AVI の既知の拡張子を拒否し、新規作成にも適用します。拡張子を変えたファイルも、PDF/GIF/PNG/JPEG/ZIP/OLE/RAR/7z/gzip/bzip2/xz/RIFF の先頭シグネチャで拒否します。本文に TAB・CR・LF 以外の C0 制御文字、DEL・C1 制御文字がある場合も拒否します。判定は保存する本文と既存の原本の両方に適用されます。

BOM 付き UTF-8、空の通常テキスト、CSV/JSON/SVG は扱えます。部分置換では BOM と未編集部分を保持します。すべてのバイナリー形式を識別するものではありません。Office は専用ツールを使ってください。PDF 編集は未対応です。重要な原本は読み取り専用にし、別の出力先を使ってください。

旧形式 `.doc` / `.xls` / `.ppt`、マクロ付き・暗号化・外部リンク・埋め込みオブジェクト付きの Office ファイルは対象外です。既存の複雑な書式の完全維持は保証しません。重要な原本は読み取り専用フォルダーに置き、出力先を分けてください。

Excel の結合セルは左上セルを明示して更新します。それ以外のセルへの書き込みは説明付きで拒否し、その XLSX 更新要求は保存しません。結合の解除や左上セルへの書き込みの置き換えは自動では行いません。

許可範囲の起点には既存フォルダーを登録します。その内部では `create_directory` で必要な子フォルダーを作り、テキスト・Office ツールでファイルを保存できます。新規ファイルは `expected_sha256: "missing"`、既存ファイルの更新は現在の SHA-256 が必要です。フォルダー作成はツールログ、成功したファイル保存は「成果・保存記録」に残ります。途中でフォルダー作成が失敗した場合、先に作ったフォルダーは残ることがあります。

**文章だけで終わり、ファイルができない場合:** 「設定 → ファイルへのアクセス」で「書き込みを許可する場所」に既存の出力フォルダーの絶対パスを登録し、保存後に新しい作業を開始してください。読み直して確認させる場合は同じフォルダーを「読み取りを許可する場所」にも登録します。依頼には「この出力先に実際に作成・保存してください」と明記します。依頼文にパスを書くだけではアクセス許可になりません。モデルの報告は保存の証拠ではないため、実際に書いた担当者の保存記録を確認してください。Local 接続先が JSON tool calling に対応していない場合、コードや手順の文章が返っても自律操作にはなりません。

直接のファイル削除・任意のシェルコマンド実行は提供しません。Python は次の明示設定で利用できます。

## 既存 Python とライブラリの利用

「設定 → Python」で、既存の CPython `python.exe` と既存ライブラリのフォルダー（通常は `site-packages`）を絶対パスで指定します。既定は無効です。Python本体やパッケージの同梱・ダウンロード・自動インストールは行いません。アプリ自身の起動用Pythonとは独立した設定です。

`python_execute` は通常のPython構文と選択したライブラリを使います。WindowsのLPACとJob Objectで隔離し、子プロセスを禁止します。ネットワーク接続は既定で禁止し、「Python のネットワーク接続を許可」（`python.network_enabled`、既定 `false`）で有効にできます。保存後に開始する新しい作業へ適用され、実行中の作業やモデル自身から変更はできません。オンではPythonが直接通信し、Webツールのプロキシ・接続先制限は適用されません。入力や読み取り可能なデータを外部へ送信できるため、必要な作業だけ有効にしてください。Windowsのネットワーク権限・ファイアウォールは引き続き適用され、localhost／同じPCへの接続は既定のloopback制限により失敗する場合があります。アプリはその例外を登録しません。

ホストの作業フォルダーを直接許可せず、スクリプトは一時作業フォルダーの相対パスを使います。読み取り許可されたファイルだけを `inputs` に列挙してコピーし、正常終了後に `outputs` に列挙したファイルだけを書き込み許可先へ公開します。出力先親フォルダーは先に作成し、既存ファイルはSHA-256で競合確認します。成功した保存は通常の保存記録に残ります。

実行時間（既定60秒）、メモリ（512MiB）、標準出力・標準エラー（合計64KiB）を設定できます。中止・制限超過・異常終了では出力を公開しません。公開途中に競合した場合は、先に成功した保存が残り、その記録とエラーを返します。Windowsの隔離機能が使えなければ拒否し、通常権限での実行に切り替えません。Linux/macOSではこのPythonツールを提供しません。

実行にはOSの基本資源・レジストリ読取と、指定したPython・ライブラリへの読み取り例外が必要です。隔離用の一時フォルダーと専用プロファイルには書き込めます。直接アクセスの境界はWindowsのLPAC権限です。WindowsでLPAC向けに公開済みの資源は、ファイル転送の `read_roots` / `deny_roots` とは別に読めるため、全Python I/Oをこれらのフォルダー設定だけで制限する機能ではありません。ライブラリの場所に秘密情報を置かないでください。子プロセス・COMや通常のユーザー設定を必要とするパッケージは動作しない場合があります。GPU利用は保証しません。`python_execute` の出力は任意バイナリーも扱うため、Office専用ツールの文書形式検査を経由しません。詳細は [SECURITY.md](SECURITY.md)。

## Selenium によるブラウザー操作

Windows では「設定 → Selenium」の「Selenium のブラウザー操作を許可」をオンにすると、`selenium_browse` で Edge / Chrome のページを表示・操作できます。**既定はオフ**です。「設定 → Python」の `python.exe` と「Python のネットワーク接続を許可」（`python.network_enabled`）も必要ですが、一般の Python 実行（`python.enabled`）はオフのままで使えます。保存した設定は、その後に開始する新しい作業へ適用します。

事前に認可された既存ファイルを用意し、次の場所を設定してください。アプリは Selenium Manager による探索・ダウンロードや、Python・ライブラリ・ブラウザー・ドライバーのインストールを行いません。

| 必要なもの | 設定する場所 |
|---|---|
| 既存の CPython `python.exe` | Python の実行ファイル |
| `selenium>=4.32,<5` とその依存パッケージ | Selenium のライブラリフォルダー（`site-packages` の絶対パス、1行に1件）。Python 側のライブラリフォルダーも読み込みます |
| 既存の Edge または Chrome | Selenium のブラウザー選択と、その実行ファイルの絶対パス |
| 対応する `msedgedriver.exe` または `chromedriver.exe` | Selenium のドライバー実行ファイルの絶対パス |

ライブラリは指定した Python と互換性があるものを使います。ブラウザー更新後はドライバーの互換性も確認してください。[Edge の対応バージョン](https://learn.microsoft.com/en-us/microsoft-edge/webdriver/)と[ChromeDriver の対応バージョン](https://developer.chrome.com/docs/chromedriver/downloads/version-selection)は公式案内を参照できます。Selenium は任意機能の依存関係であり、通常の [requirements.lock](requirements.lock) によるセットアップには含めません。

1回の呼び出しごとに、新しい専用プロファイルで headless ブラウザーを起動し、終了時に閉じます。普段のブラウザーやログイン済みプロファイルを使わず、呼び出し間のセッションも引き継ぎません。指定できる操作は HTTP(S) URL の表示と CSS セレクターによる `click` / `fill` / `read` / `wait`（最大20件）、ページのテキスト取得、任意の PNG スクリーンショット保存です。モデルが任意の JavaScript・Python・ブラウザーオプション・CDP コマンドを渡す機能や、ファイルのアップロード／ダウンロード操作はありません。クリックやフォーム送信は接続先のデータを変更する可能性があります。

スクリーンショットだけを通常のファイル権限・予約・SHA-256 競合確認で保存し、「成果・保存記録」に記録します。保存先の親フォルダーは事前に作成し、新規ファイルは `expected_sha256: "missing"` を指定します。実行時間は既定60秒（10〜300秒）、メモリは1024MiB（256〜8192MiB）、取得テキストは20,000文字（1,000〜100,000文字）です。Selenium 専用プロキシが空欄なら直接接続し、Web 検索のプロキシは引き継ぎません。

**Selenium は通常の Windows ユーザー権限で動き、Python の LPAC によるフォルダー隔離は適用されません。** Job Object はプロセスの終了・資源制限に使います。ファイル許可はスクリーンショット等のツール経由の転送を制限するもので、ブラウザー全体の OS アクセス制限ではありません。新規プロファイルでも企業 SSO 等の認証情報が完全に隔離される保証はなく、URL 検査も全通信・接続先・ローカルファイルへの OS アクセスを保証する境界ではありません。ページ内の JavaScript は動作します。許可したサイト・フォームで扱う情報を確認してください。

Selenium をオフにすると Workbench の専用ツールを使えなくなります。ただし、ネットワークを許可した一般の Python 実行まで有効にしている場合、Python から既存の外部 WebDriver サーバーへ HTTP 通信する等の操作を遮断する設定ではありません。外部送信を禁止する場合は Python のネットワーク接続もオフにしてください。詳しくは [SECURITY.md](SECURITY.md#optional-selenium-browser-boundary)。

操作対象を選べるよう、表示中のボタン・リンク・入力欄などを最大40件、ラベルと CSS セレクター付きで返します。入力値はこの一覧には含めません。iframe・Shadow DOM 内の探索には対応していません。次の呼び出しは新しいブラウザーになるため、必要な先行操作を同じバッチで繰り返します。

## API キーの保存方法

設定の各モデルプロファイルで、API キーを直接入力して保存方法を選べます。**この起動中のみ**を選び新しいキーをセットすると、以前に暗号化保存した同じプロファイルのキーを削除して置き換えます。**このWindowsユーザーに暗号化保存**は Windows DPAPI CurrentUser を使用し、同じPC・Windowsユーザー・状態フォルダーからの再起動や通常更新で読み込みます。別PC・別ユーザーにコピーして使える機能ではありません。未対応の環境や保存先に問題がある場合は選べません。

「入力・保存したキーを削除」は、選択した保存方法にかかわらず、そのプロファイルの直接入力キーと暗号化保存キーを両方削除します。指定した環境変数の値は削除せず、環境変数のキーがあれば引き続き使用します。画面には現在の取得元と保存状態だけを表示し、値は再表示しません。キー保存だけでモデルを有効化、接続確認、再試行することはありません。

保存済みキーと接続先が一致しない場合は、対象IDを表示します。保存済み設定を読み直して対象のキーを明示的に削除し、接続先を変更してから必要なキーを入力してください。読み取れない・復号できない保存ファイルは自動削除しません。暗号化キーは設定バックアップにも会話履歴にも含めません。保存先は設定画面に表示します。

## 思考表示と保存

Local の `<think>...</think>`、`reasoning_content`、Anthropic が返した thinking、OpenAI が返した reasoning summary を、回答と分けて折りたたみ表示します。クリックすると詳細を確認できます。API が返さない内部思考を取得・生成する機能ではありません。ツール往復に必要な provider 固有の署名・暗号化ブロックはメモリ内の会話で保持します。

設定は `%LOCALAPPDATA%\AgentWorkbench\settings.json`、表示用の会話・作業履歴は同じ保存先の `history/work-history.sqlite3` に保存します。通常の更新・再起動後も、保存済みの依頼、担当、ログ、報告、通信、掲示板、保存記録を選んで読めます。画面の「履歴の保存先・上限」で実際の保存先を確認でき、保存・読み込みエラーは画面に表示します。API キーや環境変数の値は設定・表示用履歴に保存しません。明示して暗号化保存したキーは別の保護ファイルから読み込み、環境変数のキーは次の起動時の環境を使います。設定を変更した後は新しい仕事を開始してください。

復元した履歴は**閲覧専用**です。終了時に未完了だった作業は「中断」と表示し、再開・追加指示・質問への回答・メール送信・掲示板投稿を行いません。「この依頼を新しい下書きに使う」で依頼文を取り出し、現在の設定と権限で新しい作業を始められます。モデル用の私的な会話文脈、署名・暗号化ブロック、実行待ちの操作、承認状態は復元しません。公開画面に表示する思考テキストは履歴に含みます。**この機能の導入前に終了して消えた履歴は復元できません。**

同じPC・同じWindowsユーザーで通常の `Launch.bat` を使う場合、アプリを別のバージョンのフォルダーへ展開しても保存済み設定を引き継ぎます。新しい項目だけ既定値を補い、既存の入力を初期化しません。`Setup.bat` はこの設定ファイルを削除しません。`--state-dir` を指定した場合はその保存先を使用します。実際の保存先は「設定 → 設定の引き継ぎ」に表示します。

別PC・別の保存先へ移す場合は、旧画面で「保存済み設定をバックアップ」を押し、新画面で「設定ファイルを読み込む」→内容を確認→「設定を保存」の順に操作してください。以前の `settings.json` も読み込めます。読み込みだけでは現在の設定や接続先を変更しません。直接入力したAPIキーや環境変数の値、会話・実行履歴はバックアップに含みません。フォルダーやPython・WebDriver等の場所が変わった場合は、その項目を修正して保存してください。

更新後に保存済みのパスが見つからなくなっても、元の値を保持して設定画面を開けます。表示された項目を修正して保存するまで、作業開始・接続テスト・Copilotの自動起動を止めます。設定ファイルを初期値で上書きしたり、別の実行ファイルを自動選択したりはしません。

ブラウザーのタブを閉じる・再読み込みする操作は、サーバーや実行中の作業を停止しません。画面の「停止」は選択したチームだけを止め、履歴を保持します。起動したコンソールを閉じるか Ctrl+C でサーバーを終了します。終了前に、残したい報告・保存記録を「成果・保存記録」で1件ずつ選び、`.txt 保存` を押してブラウザー側のダウンロード完了を確認してください。保存履歴には、過去の保存に成功した表示用の記録を蓄積します。起動中の表示から外れた保存済み記録も再起動後に閲覧できますが、保存前に省略された本文やモデル内部の会話文脈は復元しません。未送信の下書きや表示の選択状態は復元を保証しません。ブラウザーを終了して認証 Cookie を失うと、サーバーに履歴が残っていても再接続できないことがあります。

実行履歴は1起動あたり20作業までです。完了・停止した作業も数え、21件目は開始できません。古い作業を自動削除して枠を空けることはありません。上限に達した場合は、必要な報告・保存記録を保存し、すべての作業完了後にサーバーを再起動してください。保存できた履歴は再起動後に閲覧でき、新しい起動の20作業枠には数えません。「この起動中のみ」で入力した API キーは引き継ぎません。明示して暗号化保存したキーは同じPC・Windowsユーザー・保存先で引き継ぎます。保存済み設定と実際の作業ファイルは残ります。保存記録から現在のファイルの存在・内容を確認したことにはなりません。

## 安全性と公開範囲

初期状態は読み書き権限なし、検索なし、Python・Selenium 無効です。ファイルツールの read / write は独立し、deny が優先します。パストラバーサル、UNC、NTFS 代替ストリーム、symlink / junction / hardlink、アプリ自身への編集を拒否します。書き込みは SHA-256 による競合確認とアトミック置換を行います。別の作業者による重複編集を防ぐ予約機能もあります。

許可したファイルの内容は選択したモデルに送られます。クラウドの PM と Local の作業者が相談すると、Local が読んだ内容が PM に共有される場合があります。検索語や取得 URL も外部へ送られます。機密文書は必要な範囲だけ許可してください。外部送信が禁止される仕事では Web・Python のネットワーク接続・Selenium を無効にし、PM・作業者すべての接続先と、接続先での保存・再転送・学習利用が社内要件を満たすことを確認してください。Local はこの PC またはプライベート LAN の API に接続する設定であり、会社の承認や外部への再転送がないことを保証しません。

プロンプトインジェクションを完全に検出する保証はありません。外部情報を権限変更として扱わず、実際の操作をコード側の権限・予算で制限します。**同一ユーザー権限で動く悪意ある別プロセスを隔離する OS サンドボックスではありません。** 詳細は [SECURITY.md](SECURITY.md)。

## 結果と保存記録

`0.1.1.dev21` は、完了報告・人への質問が成功した直後にツール回数や実行時間の上限へ達した場合、同じ応答内の実行しない後続ツールによって成功済みの状態がエラーへ変わる問題を修正します。後続ツールは実行せず、消費済みの回数は戻しません。期限切れの作業は再開できません。画面デザイン・設定・権限は変更していません。

選択中のエージェントの「結果」から、このターンの最終応答・明示的な完了報告と、実際に保存に成功したファイルの記録を確認できます。応答はモデルの報告であり、内容の正しさの検証ではありません。追加依頼後の以前の応答は過去のものとして表示します。

保存記録のパス・サイズ・SHA-256 は保存時点の情報です。その後の変更・削除や現在の読み取り可否は確認していません。ファイル本体をダウンロードする機能ではありません。本文／パスのコピーと、選択した応答または保存記録の UTF-8 テキスト保存は、ボタンを押したときだけ行います。思考の詳細や API の内部データは含めません。

起動中のメモリに、担当者ごとに最新20件の応答（各24,000文字まで）・64件の保存記録を保持します。件数超過・本文の省略は表示します。ログの保持は従来どおり最新200件です。各時点の表示用記録を自動保存し、以前の保存に成功した記録は起動中の表示から外れても蓄積します。再起動後は保存したログ・報告・保存記録を閲覧専用で開きます。保存前に省略された本文や旧版で失った記録は復元しません。保存上限は500作業・1作業16 MiB・合計256 MiB・各一覧50,000件で、上限や書き込み失敗を画面に表示します。通信タイムラインの表示は最新100件、掲示板は最大200件です。保存済み履歴を黙って削除して空きを作ることはありません。チームの停止やサーバーの終了では、既に保存した作業ファイルを削除しません。保持上限で省略される前に、必要な報告・保存記録を明示的に保存してください。

### 0.1.1.dev4: 開始前の確認

新しい作業では、保存済み設定を使い、開始条件・読み取り/書き込み範囲・拒否範囲・Web の状態・送信される可能性のある接続先を表示します。この確認はネットワークや推論を実行せず、開始時にも同じ条件を再確認します。未保存の設定は適用されません。フォルダー未指定でも文章だけの作業は開始できます。作業者数 0 では未使用の worker 設定は開始を妨げません。

ヘッダーの Workbench 接続は、この PC のアプリとの通信です。LOCAL APP はアプリの実行場所を表し、モデルや Web への通信がすべてローカルという意味ではありません。モデル一覧の確認は明示的に押したプロファイルの GET /models のみです。モデル名は手入力でき、一覧にない別名もそのまま利用できます。一覧の取得・モデルの存在は、推論やツールが動くことの証明ではありません。設定の変更や設定画面を閉じた後の古い確認結果は表示しません。

### 0.1.1.dev6: 履歴が増えたときの画面更新

画面更新では担当者全員の状態を取得し、詳しいログ・報告・保存記録は選択中の担当者だけを読み込みます。切り替え中は読み込み表示になり、前の担当者の内容をコピーしないようにします。古い通信の応答が新しい選択を上書きしないようにし、同じ内容の更新では表示やフォーカスを保ちます。

表示履歴の保持件数と起動中20作業の上限は変わりません。保存済み履歴は別枠で表示し、自動削除や作業ファイルの削除はしません。既存の完全な状態取得 API も引き続き利用できます。

### 0.1.1.dev7: 過去の作業に使ったモデル設定

担当者一覧と作業ログの見出しは、その作業を開始したときのプロファイル名・接続方式・モデル設定を表示します。設定画面で同じプロファイルを変更・削除しても、過去の表示は変わりません。モデル名は設定値であり、接続先が実際に使ったモデルや別名の解決先を確認したものではありません。開始時の情報がない場合は、そのことを表示します。

明示的な `.txt` 保存には、選択した記録の作業 ID・担当者・エージェント ID・プロファイル ID と開始時のモデル設定も含まれます。プロファイル名・モデル名・担当者名は JSON 形式の引用文字列として記録し、名前に含まれる改行などを区別します。API の接続先・プロキシ・キーの参照先・作業方針・許可フォルダーは、この追加メタデータに含めません。本文や保存パスのコピーは従来どおりです。保存記録はファイル操作の記録であり、モデルによる内容の検証ではありません。

### 0.1.1.dev9: キー変更後も過去の表示を保護

認識済み API キーは、キーの差し替え・削除、環境変数の参照先変更後も、過去の依頼・担当名・質問・ログ・報告・保存記録で `[redacted]` と表示します。変更前に開始した応答が遅れて届いた場合や、完了済みの会話を続けた場合も対象です。コピー・`.txt` 保存には、受け取った保護済みの表示データを使います。

このため、古いキーの一致照合用データもアプリ終了までメモリ内に残ります。認証や設定ファイルの保存には使いません。1起動あたり512種類・合計2 MiB（UTF-8換算）の上限を超える変更は、適用せずにエラーを表示します。必要な作業を保存してからアプリを再起動してください。これは任意の機密情報や加工済みキーを見つける機能ではなく、モデルへ送る会話や作業ファイルの内容を変更する機能でもありません。すでに画面・クリップボード・保存ファイルへ渡った内容の取り消しはできません。

暗号化保存したキーがあるプロファイルの削除や接続先識別情報の変更は、先に「入力・保存したキーを削除」を行うまで拒否します。プロファイルの削除、接続方式・API 接続先・キーの環境変数参照先の変更時には、従来のメモリ内キーを新しい接続先へ引き継ぎません。必要ならキーを再入力してください。表示名・モデル名だけの変更では引き続き利用できます。`search` は旧設定との互換性のため予約されている ID です。以前この ID をモデルプロファイルへ手動で設定していた場合は、設定ファイルのプロファイル ID を別名へ変更してください。設定の表示名・モデル名・方針などは入力どおりに保存されるため、そこへキーを貼り付けないでください。

### 0.1.1.dev11: 開始・停止の応答が遅れたとき

開始の受付後に画面更新だけが失敗した場合は、受け付けられた作業 ID を表示し、実行一覧に現れるまで開始ボタンを無効にします。通常の状態確認を続けますが、開始要求は自動で再送信しません。開始応答そのものが確認できない場合は未確認と表示します。重複作業を避けるため、実行一覧と接続状態を確認してから再送信が必要か判断してください。

待っている間に別の作業を選んだり、依頼を編集したり、ダイアログを開き直した場合、遅れて届いた応答でその操作を取り消しません。新しい下書きもそのまま残します。停止要求の受付中は対象の停止ボタンを無効にし、別の作業へ切り替えた後は、その作業自身の状態から操作できるかを判断します。状態確認と操作の記録は開いている画面内だけで管理し、ページ再読込後の送信重複を防ぐサーバー機能は追加していません。

### 0.1.1.dev12: 保存済み接続先のキーを差し替えて続行

認証エラーでチームが待機中になっていても、設定画面で保存済みプロファイルのメモリ内キーを差し替えられます。接続先 URL・モデル・プロキシ・権限・上限などの設定は、実行中は引き続き変更できません。入力欄の下に表示される保存済みの ID・接続方式・URL・プロキシを確認し、キーは本人がアプリの専用欄へ入力してください。同じ URL でも、別のプロファイル ID のキーは変更しません。

変更は同じ保存済みプロファイルを使う全チームの次のリクエストに反映されます。送信済みのリクエストには影響せず、セットするだけで接続確認・自動再試行はしません。認証できることを確認した結果でもありません。エラーで待機中の作業を続ける場合は、対象エージェントに明示的な指示を送ってください。経過時間・呼び出し数・ターン・コンテキストなどの上限はリセットされず、停止済みのチームも再開できません。

未保存の設定がある場合は、キー欄を使う前に設定を保存するか「変更を破棄・保存済み設定を読み直す」を選びます。読み直しはサーバーの設定を書き換えず、仕事・会話の下書きやチーム選択を維持します。別の画面で設定が変更された場合も、古い接続先を見ながら入力したキーは拒否します。キー欄はモデル接続用です。DuckDuckGo・SearXNG・ページ取得では検索用 API キーを使用しません。

送信中は同じキーの二重送信を防ぎます。キーの値は送信時・設定画面を閉じたとき・設定変更時に入力欄から消し、再表示しません。応答を確認できなかった場合は自動再送信せず、結果が未確認であることを表示します。「キー設定あり」だけでは今回の差し替えが成功した証明になりません。現在の版では、明示したキーだけWindowsユーザー単位で暗号化保存できます。外部保管サービス・アカウント上でのキー発行や失効は行いません。


### 0.1.1.dev14: 履歴の保持と終了前の保存

SESSIONS に起動中の作業数と20件の上限、終了前の保存案内を表示します。「成果・保存記録」の既存の `.txt 保存` は選択中の1件だけを保存し、作業ファイル本体は含みません。「履歴の保持・終了について」から、担当者ごとの保持上限と、タブを閉じる・チームを停止する・サーバーを終了する操作の違いを確認できます。現在の版では表示用履歴を自動保存します。一括エクスポート、未送信下書きの復元、認証復旧は追加していません。


### 長い会話の自動圧縮（0.1.1.dev36更新）

文脈の予算が埋まってきたら、古いやり取りを同じ API・モデルで要約し、作業を続けます。
初期値は有効で、既存設定にも適用します。設定の「古い会話を自動で要約する」で無効にできます。
元の依頼・直近2件の人の発言をそのまま残し、通常の要約では直近のやり取りも保持します。ツール呼び出しと結果の組は分割しません。
要約には目的、制約、決定、根拠、未完了の仕事、不確実な点を残すよう依頼しますが、情報の抜けや誤りはあり得ます。
過去の承認を要約だけで判断せず、保持された元の記録を確認し、取得できなければ人に質問する方針です。

要約も追加のモデル呼び出しです。選択した接続先へ送信し、通常の呼び出し回数・制限時間を使い、API 料金がかかる場合があります。
元の履歴は担当者ごとに最大40万文字・2000件までメモリに保持します。古い記録や単独で上限を超える記録は除外し、画面に件数を表示します。
要約回数と処理中の状態も作業ログ欄で確認できます。モデル用の会話文脈自体は永続化しません。再起動後に読める表示用履歴とは別で、作業の自動再開や仕事をまたぐ長期記憶はありません。

AI要約の形式不正・長すぎる応答・短縮不足や、大きな調査結果が要約入力に収まらない場合は、記録ID付きの短い抜粋へ切り替えて続行を試みます。これは内容を理解してまとめた要約ではなく、一部を省略した参照データです。省略と切り替えはログに表示し、元記録の保持上限は変えません。必要な根拠は `read_context_history` で確認します。1件の大きな記録は、マスキング済みのJSONを範囲指定して分割読取できます。すでに保持上限から除外された記録は復元できません。

古い記録を優先して整理し、それでも文脈の上限を超える場合に限って、直近の人以外のやり取りも完全な組ごとに抜粋へ置き換えます。元の依頼や直近の人の指示を削って処理を続けることはありません。抜粋を新しい承認や、検証済みの根拠として扱うこともありません。

文字の上限には会話だけでなく作業方針・ツール定義も含みます。プロファイルの「モデル文脈予算」は任意です（0 は無効）。
モデルに合わせて指定すると、UTF-8 byte 数による保守的な token 推定に出力上限・追加余白を加えて判定します。
正確な token 数や実モデルへの収容を保証するものではありません。元の依頼・直近の人の指示・固定の作業方針だけでも大きすぎる場合、認証・通信エラー、時間切れなどは引き続き停止理由になります。要約失敗を理由に無制限にAPIを呼び直したり、実行予算を増やしたりはしません。
回数や時間の上限がリセットされることはありません。設定・詳しい制約は [構成の説明](docs/ARCHITECTURE.md#context-memory-and-automatic-compaction-011dev31) を参照してください。
