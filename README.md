# Agent Workbench

Windows 11 で動く、Local LLM・OpenAI・Anthropic のためのエージェント作業アプリです。PM が作業者を作り、役割を割り当て、メールで相談し、結果を受け取って作業をまとめます。同じ API を使う役割別チームと、異なる API を使う混成チームの両方に対応します。

Codex CLI / Claude Code / WSL / Docker / Microsoft Office のインストールは不要です。LLM サーバーそのものは別途用意してください。ORRERY のソースや素材は使用せず、新規に実装しています。

## Windows で起動

必要なもの: Windows 11、承認済みの通常版 **64-bit CPython 3.11〜3.13**（3.13 推奨）、Edge または Chrome。

1. ソース ZIP を、自分が書き込めるローカルフォルダーにすべて展開します。
2. **`Setup.cmd` をダブルクリック**し、`Setup complete` を確認します。
3. **`Launch.cmd` をダブルクリック**します。起動したコンソールで Ctrl+C を押すと停止します。

通常のセットアップ・起動に PowerShell、管理者権限、Git、ビルドツールは不要です。Python 本体は会社で承認された方法で用意してください。社内ポリシーによる実行禁止やセキュリティ警告を回避する設定は行いません。

コマンドプロンプトから診断・プロキシ・オフラインインストールも指定できます。

```bat
Setup.cmd --check
Setup.cmd --proxy "http://proxy.example.local:8080"
Setup.cmd --wheelhouse "C:\Approved Packages\wheelhouse"
```

上のプロキシは例です。会社の指定値を使ってください。証明書は `--certificate "C:\Certificates\company-ca.pem"` で指定できます。通常モードは既存 pip / proxy 設定を引き継ぎます。パッケージはハッシュを確認した wheel のみ利用し、依存のソースビルドや TLS 検証無効化は行いません。

既定ポートは `8818`。二重起動は既に起動中であることを表示します。既存のブラウザー画面を使ってください。別アプリが使っている場合は `Launch.cmd --port 8820` で起動してください。アプリはソースフォルダーを利用するため、セットアップ後にフォルダーを移動しないでください。

**詳しい手順・Python の指定・社内 CA・オフライン wheel の準備・エラー対処は [Windows 11 セットアップガイド](docs/WINDOWS_SETUP.md) を参照してください。**

## 最初の設定

1. **設定 → API プロファイル**で接続先、モデル名を入力して保存します。モデル名は利用中のサーバーやアカウントで有効なものを入力してください。固定の推奨モデル名は埋め込んでいません。
2. クラウド API キーは「今回の起動中だけ使う API キー」に入力してセットします。環境変数 `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` も利用できます。キーは設定ファイルに保存されません。
3. 作業用フォルダーをエクスプローラーで作成し、**読み取りを許可する場所**と**書き込みを許可する場所**に絶対パスを登録します。例えば `C:\AgentWork\documents`。アプリ自身のフォルダーや状態フォルダーは常に拒否されるので、作業用に別の場所を使ってください。
4. **チームで作業**に戻り、依頼、PM、作業者に許可するプロファイル、作業者数を選んで開始します。

「接続を確認」は `/models` の取得だけです。推論や有料リクエストの成功を保証するチェックではありません。

| 接続方式 | API ベース URL の例 | 使用する API |
| --- | --- | --- |
| Local / OpenAI 互換 | `http://127.0.0.1:11434/v1` または実際のポート | `/chat/completions` |
| OpenAI | `https://api.openai.com/v1` | `/responses`、`store:false` |
| Anthropic | `https://api.anthropic.com/v1` | `/messages` |

Local サーバーには OpenAI 互換の **JSON tool calling** が必要です。通常のチャットだけに対応するサーバー、テキスト中にツール名を書くだけのモデルでは自律操作できません。Qwen 等を使う際は、サーバー側の chat template / tool parser も対応させてください。生成されたコードや JSON 風の文章を勝手に実行するフォールバックはありません。

Local は loopback と、数値で指定した RFC1918 / IPv6 ULA の LAN アドレスに対応します。環境変数を含め、プロキシは常に使いません。LAN の HTTP は平文通信です。社内ネットワークで必要な認証・HTTPS は推論サーバー側で設定してください。

## チームの使い方

同じ Local プロファイルだけを PM・作業者に指定すると、単一モデルが別々の会話と役割を持ちます。OpenAI の PM に Local と Anthropic の作業者を許可すると、PM はその範囲で担当と API を選べます。作業者同士の連絡も同じチーム内で行えます。

依頼例:

> 読み取りを許可したフォルダーの資料を整理してください。調査担当とレビュー担当に分担し、通常の判断はチーム内で相談してください。許可した出力フォルダーに summary.docx と tasks.xlsx を作成し、読み直して検証してください。元資料は変更しないでください。目的が変わる判断だけ質問してください。

作業者の完了通知やメールで PM / 相手の次のターンが自動的に始まります。`ask_user` の質問は人が回答するまで待機し、仲間のメールでは解除されません。作業方針は設定から全文確認・編集できます。実際の委任や質問の頻度はモデルの能力と指示にも依存します。

| 設定 | 意味 |
| --- | --- |
| 作業者の上限 | 1つの仕事で作れる独立した worker の数。PM は別に1人。0ならPMだけ。既存 worker は追加依頼で再利用 |
| 自動連携回数の上限 | 1つの仕事のチーム全体で共有する委任・連絡回数。既定24回、0〜1000回で設定。0なら自動連携なしでPMが作業 |
| Local 同時リクエスト数 | 全チーム・全 Local プロファイル合計の推論枠。例: worker 4人、推論枠1なら順番に推論 |
| キューの待機上限 | 推論枠・開始間隔・GPU 状態を待つ時間の上限 |
| リクエスト上限 | API 応答を待つ時間。Local はプロファイルと共通設定の小さい方 |
| 開始間隔 | Local リクエストの開始間に必要な秒数 |
| 再試行 | Local の HTTP 429 / 503 だけを指定回数まで再試行。接続断による曖昧な処理の再実行はしない |
| 実行予算 | チーム全体のモデル呼び出し数・ツール数・時間、および会話長・出力・各エージェントのターン数 |

**設定 → 作業の上限 → 自動連携回数の上限**から変更できます。新しい作業には設定した上限が適用され、作業画面に「自動連携 使用回数 / 上限」を表示します。既存の設定ファイルに項目がなくても、24回を適用します。

作業者の作成と最初の委任、エージェント間のメール、作業者からPMへの自動完了・エラー通知が、正常に届くたびに各1回を消費します。人の依頼・回答、通常のモデル呼び出しやファイル操作、失敗した連絡は数えません。上限後は新しい委任・連絡を停止し、開始済み・待機中の作業は続行できます。上限で連絡が止まった場合は画面に表示し、自動でチーム全体を完了扱いにしません。人が追加指示を送ってPM単独で仕上げることはできますが、回数はリセットされません。上限を変更して連携を続ける場合は作業を停止し、設定を保存して新しい作業を開始してください。

「停止」は新しい操作を止め、実行中のローカルファイル操作の終了を待ちます。外部 API のサーバー側推論の中止や課金取り消し、既に保存したファイルの巻き戻しは保証しません。実行時間の上限到達後は新しいツール操作を始めませんが、開始済みの安全なファイル保存は完了を待ちます。

## GPU / VRAM

NVIDIA の `nvidia-smi` から **この PC の GPU 全体**の使用 VRAM と使用率を取得し、しきい値を超えている間は新しい Local リクエストの開始を待ちます。GPU 番号、確認間隔、待機上限、取得不能時に拒否するかを設定できます。各しきい値の `0` はその条件を無効にします。

**これは開始前の監視です。VRAM / GPU 使用量のハード上限ではありません。** リクエスト開始後の割り当てを止めたり、外部推論サーバーの GPU メモリを解放したりする機能はありません。モデル常駐分も使用 VRAM に含まれるため、常駐量より小さいしきい値では開始できません。厳密な割り当て制限は推論サーバー側で設定してください。

LAN 上の Local サーバーでは、この PC の GPU 値を代用できないため GPU 監視を有効にできません。AMD / Intel の監視には未対応です。推論の同時数や待機上限は GPU 監視を無効にしても有効です。

## Web 検索とプロキシ

既定では無効です。検索方式は SearXNG JSON API または Brave Search API を選択します。

- SearXNG: 使用するサーバーの `/search` URL。JSON 出力が有効なサーバーが必要です。LAN 内でも HTTPS が必要です。HTTP の例外は `localhost` / `127.0.0.1` / `[::1]` のみです。
- Brave: `https://api.search.brave.com/res/v1/web/search`。検索キーはメモリ欄または `BRAVE_SEARCH_API_KEY`。
- 検索用プロキシ例: `http://127.0.0.1:8080`。**検索と検索後のページ取得の両方**に適用されます。失敗時に直接接続へ切り替えません。
- OpenAI / Anthropic にもプロファイルごとの明示プロキシがあります。検索の設定とは独立しています。

HTTP(S) プロキシに対応します。SOCKS、PAC、URL に埋め込んだ認証情報、独自 CA の登録 UI は未対応です。Local はこれらの設定の影響を受けません。Web の取得対象は公開 HTTP(S) テキストのみで、JavaScript は実行しません。内部・メタデータアドレスや危険なリダイレクトを拒否します。明示した SearXNG 検索サーバーだけは内部の接続先も利用できます（LAN 内も HTTPS が必要）。

## ファイルと Office

| 形式 | 対応する操作 | 制限 |
| --- | --- | --- |
| UTF-8 テキスト | 読む、検索、作成、置換、SHA-256取得 | 既知の文書・バイナリー形式、非 UTF-8、NUL・バイナリー制御文字への上書き不可 |
| `.docx` | 段落・表の読み取り、作成、段落・セルの編集 | Word COM / マクロ / OLE / 外部参照なし |
| `.xlsx` | シート・セル範囲の読み取り、セル更新、シート作成 | 許可した通常関数のみ。数式の再計算エンジンなし |
| `.pptx` | スライドテキストの読み取り、作成、既存テキストの編集 | PowerPoint 全機能・描画の完全再現ではない |

読み取り・検索は UTF-8 と NUL の有無で判定します。破壊的なテキスト操作（作成・上書き・部分置換）は追加の保護を行います。PDF、Office、OpenDocument、主要な画像・圧縮形式、および WAV/AVI の既知の拡張子を拒否し、新規作成にも適用します。拡張子を変えたファイルも、PDF/GIF/PNG/JPEG/ZIP/OLE/RAR/7z/gzip/bzip2/xz/RIFF の先頭シグネチャで拒否します。本文に TAB・CR・LF 以外の C0 制御文字、DEL・C1 制御文字がある場合も拒否します。判定は保存する本文と既存の原本の両方に適用されます。

BOM 付き UTF-8、空の通常テキスト、CSV/JSON/SVG は扱えます。部分置換では BOM と未編集部分を保持します。すべてのバイナリー形式を識別するものではありません。Office は専用ツールを使ってください。PDF 編集は未対応です。重要な原本は読み取り専用にし、別の出力先を使ってください。

旧形式 `.doc` / `.xls` / `.ppt`、マクロ付き・暗号化・外部リンク・埋め込みオブジェクト付きの Office ファイルは対象外です。既存の複雑な書式の完全維持は保証しません。重要な原本は読み取り専用フォルダーに置き、出力先を分けてください。

フォルダーは既存のものを登録します。現在のツールはフォルダー作成・ファイル削除・任意コマンド実行を提供しません。エージェントが Python / PowerShell / npm 等を実行することはできません。このアプリでコードを編集できても、ビルドやテストの実行はユーザー側で行います。

## 思考表示と保存

Local の `<think>...</think>`、`reasoning_content`、Anthropic が返した thinking、OpenAI が返した reasoning summary を、回答と分けて折りたたみ表示します。クリックすると詳細を確認できます。API が返さない内部思考を取得・生成する機能ではありません。ツール往復に必要な provider 固有の署名・暗号化ブロックはメモリ内の会話で保持します。

設定は `%LOCALAPPDATA%\AgentWorkbench\settings.json` に保存します。API キー、会話、実行履歴はプロセスのメモリ内だけです。アプリを終了すると消えます。自動セッション復旧やバックグラウンド常駐サービスはありません。実行履歴は1起動あたり20件までです。設定を変更した後は新しい仕事を開始してください。

## 安全性と公開範囲

初期状態は読み書き権限なし、検索なしです。read / write は独立し、deny が優先します。パストラバーサル、UNC、NTFS 代替ストリーム、symlink / junction / hardlink、アプリ自身への編集を拒否します。書き込みは SHA-256 による競合確認とアトミック置換を行います。別の作業者による重複編集を防ぐ予約機能もあります。

許可したファイルの内容は選択したモデルに送られます。クラウドの PM と Local の作業者が相談すると、Local が読んだ内容が PM に共有される場合があります。検索語や取得 URL も外部へ送られます。機密文書は必要な範囲だけ許可し、外部送信できない仕事では Local のみ・Web 無効にしてください。

プロンプトインジェクションを完全に検出する保証はありません。外部情報を権限変更として扱わず、実際の操作をコード側の権限・予算で制限します。**同一ユーザー権限で動く悪意ある別プロセスを隔離する OS サンドボックスではありません。** 詳細は [SECURITY.md](SECURITY.md)。

## 検証と開発

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pip check
```

テストは API キーなしで実行できます。HTTP テストサーバーを使い、Responses / Messages / Chat Completions の実通信、混成チームの自動委任と復帰、Office 3形式の作成・再読込、プロキシ、範囲外アクセス拒否、停止時の書き込み完了待ちを検証します。実際の有料 API や実 LLM の品質評価は別途必要です。

Edge の UI 確認用に `tools/browser_smoke.cjs` を同梱しています。開発用 Node.js と Playwright を利用できる環境で `node tools/browser_smoke.cjs` を実行します。UI のチーム表示は模擬データ、認証・設定保存は実サーバーで確認します。結果は git 対象外の `runtime/verification` に出ます。

構成と追加の制約は [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)、検証範囲は [docs/VALIDATION.md](docs/VALIDATION.md)。配布はこのソースからの editable install が対象です。単独 wheel / exe の配布には未対応です。
